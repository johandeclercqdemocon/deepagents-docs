# Chapter 6 — Planning

A long task needs somewhere to keep "what remains". Without it, the agent's only record is a
transcript it is progressively summarising away, and by turn twenty the third of your five
requirements has quietly evaporated.

The harness's answer is a todo list the agent maintains as it works. This chapter is also the
first place where the published advice and the installed library disagree.

## Planning is not on by default

Every write-up of Deep Agents — including the official skill description — says planning is
built in and enabled by default. Against deepagents 0.7.11:

```
default                  ['ls', 'read_file', 'write_file', 'edit_file', 'delete', 'glob', 'grep', 'task']
+ TodoListMiddleware     ['ls', 'read_file', 'write_file', 'edit_file', 'delete', 'glob', 'grep', 'task', 'write_todos']
```

**No `write_todos` in the default set.** You add it yourself:

```python
from langchain.agents.middleware import TodoListMiddleware

agent = create_deep_agent(model=model, middleware=[TodoListMiddleware()])
```

Note where it comes from: `langchain.agents.middleware`, not `deepagents`. Planning is a
LangChain middleware the harness composes, which is Chapter 5's layering showing through.

The failure mode is quiet. Your agent works, never plans, and gradually loses track on long
tasks — and you have no reason to suspect the tool is simply absent. **Check what your model
is actually offered** before assuming a capability is present:

```python
model.bound_tools    # with the book's ScriptedModel; or read your trace
```

## Using it

The model calls `write_todos` with the whole list, every time — it replaces rather than
patches:

```python
write_todos(todos=[
    {"content": "Read the logs",                 "status": "in_progress"},
    {"content": "Check config against the runbook", "status": "pending"},
    {"content": "Write findings",                "status": "pending"},
])
```

Later, it rewrites the list with updated statuses:

```
final todos: [{'content': 'Read logs', 'status': 'completed'},
              {'content': 'Write up', 'status': 'in_progress'}]
```

The list lands in state under `todos`, so you can read it after a run — or mid-run, from a
checkpoint (Chapter 22).

Statuses are constrained. An invented one is rejected:

```
Error invoking tool 'write_todos' with kwargs {'todos': [{'content': 'a', 'status': 'nonsense'...
```

The three that work are `pending`, `in_progress`, `completed`.

## What it is actually for

It is easy to dismiss as bookkeeping. Two things make it worth the tokens.

**It survives summarisation.** When conversation history is compressed (Chapter 17), the todo
list is *state*, not transcript. The plan is the one thing that does not get squeezed.

**It is a progress signal for you.** A long-running agent is otherwise opaque. Reading `todos`
mid-run tells you where it is, and a list that has not changed in ten turns tells you it is
stuck — which is the single most useful operational signal in Part IV.

What it is *not* is a scheduler. Nothing enforces the plan. The agent may ignore its own list,
mark things complete that are not, or never update it. It is a note to itself, and its value
is real but advisory.

## Getting good plans

The plan is generated by the model, so it responds to prompting:

**Ask for one explicitly.** *"Before you begin, write a plan with `write_todos`."* Without
this many models start work immediately and only plan when they get lost.

**Ask it to keep the list current.** *"Mark each item complete as you finish it."* An agent
that plans once and never updates gives you a stale list, which is worse than none because it
looks like progress.

**Keep it coarse.** Five items, not thirty. A plan with one item per tool call is a transcript
with extra steps and costs tokens on every turn.

`scout`'s prompt does not currently ask for a plan — its script writes one because the book
needs it deterministic. In a real agent, say so in the system prompt.

## When to skip it

Planning costs a tool definition on every call plus the list in state. Skip it when:

- The task is a handful of turns. There is nothing to lose track of.
- The work is a fixed sequence you already know — that is a chain, or a graph (Chapter 31).
- The agent has one job.

Enable it when the task is genuinely open-ended and long, which is the case the harness exists
for.

## Try it

Prove the default first — this is the finding to see for yourself:

```bash
uv run python -c "
from deepagents import create_deep_agent
from langchain.agents.middleware import TodoListMiddleware
from examples.scout.fakes import ScriptedModel

for label, mw in (('default', []), ('+ TodoListMiddleware', [TodoListMiddleware()])):
    m = ScriptedModel(script=['ok'])
    create_deep_agent(model=m, middleware=mw).invoke({'messages':[{'role':'user','content':'hi'}]})
    print(f'{label:22} write_todos offered: {\"write_todos\" in m.bound_tools}')
"
```

Then watch a plan get written and updated:

```bash
uv run python -c "
from deepagents import create_deep_agent
from langchain.agents.middleware import TodoListMiddleware
from examples.scout.fakes import ScriptedModel

script = [
  {'text':'plan','tool_calls':[{'name':'write_todos','args':{'todos':[
      {'content':'Read logs','status':'in_progress'},{'content':'Write up','status':'pending'}]}}]},
  {'text':'update','tool_calls':[{'name':'write_todos','args':{'todos':[
      {'content':'Read logs','status':'completed'},{'content':'Write up','status':'in_progress'}]}}]},
  'done']
out = create_deep_agent(model=ScriptedModel(script=script), middleware=[TodoListMiddleware()]).invoke(
    {'messages':[{'role':'user','content':'go'}]})
for t in out['todos']:
    print(f\"  [{t['status']:11}] {t['content']}\")
"
```

Then try `status: 'nonsense'` and watch it be rejected.

## Takeaways

- **`write_todos` is not enabled by default in deepagents 0.7.11**, despite what nearly every
  write-up says. Add `TodoListMiddleware` from `langchain.agents.middleware`.
- The failure is silent: the agent works, never plans, and loses the thread on long tasks.
  **Check what your model is actually offered.**
- The model rewrites the **whole list** each time; statuses are `pending`, `in_progress`,
  `completed`, and anything else is rejected.
- The plan lives in state under `todos`, readable after or during a run.
- It is worth the tokens because it **survives summarisation** and is your best **progress
  signal** — an unchanged list means a stuck agent.
- It is **advisory, not enforced.** Nothing makes the agent follow or update it.
- Ask for a plan explicitly, ask for it to be kept current, and keep it coarse — five items,
  not thirty.
- Skip it for short tasks and fixed sequences.
